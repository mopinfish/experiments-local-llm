# 地理的POIクエリタスクにおけるRAGとファインチューニングの性能比較研究

## 概要 (Abstract)

本研究では、地理的POI（Point of Interest）クエリタスクにおいて、Retrieval-Augmented Generation（RAG）とParameter-Efficient Fine-Tuning（PEFT）の性能を比較評価した。渋谷駅周辺の1,046件のPOIデータを用いて、Qwen2.5-7B-Instructモデルに対するQLoRAファインチューニングを実施し、55件のテストケース（5段階の難易度レベル）で評価を行った。

実験の結果、以下の主要な知見が得られた：
1. RAGとファインチューニングの組み合わせ（FT+RAG）が最高スコア78.5ptを達成
2. タスク特性により最適なアプローチが異なる（基礎検索ではRAG優位、意思決定支援ではFT優位）
3. 両アプローチの相補性が実証され、ハイブリッドアーキテクチャの有効性が示された

本報告書では、実験の設計、実施方法、結果、および今後のシステム開発への示唆について詳述する。

## 1. 序論 (Introduction)

### 1.1 研究背景

大規模言語モデル（LLM）を地理情報システムに応用する際、外部知識の統合方法として主に2つのアプローチが存在する：

1. **Retrieval-Augmented Generation (RAG)**: 推論時に外部データベースから関連情報を検索し、コンテキストとしてLLMに提供する手法
2. **Fine-Tuning**: ドメイン固有のデータでモデルのパラメータを更新し、知識をモデル内部に埋め込む手法

本プロジェクトでは、Phase 6までにRAGベースの構造化システムを構築し、91.6ptのスコアを達成していた。Phase 7以降の複数エリア対応・全国展開に向けて、ファインチューニングアプローチの有効性を検証し、最適なアーキテクチャ選定の指針を得ることが本研究の目的である。

### 1.2 研究目的

本研究では以下の4つの仮説を検証する：

| 仮説ID | 仮説内容 |
|--------|---------|
| H1 | ファインチューニングモデルはL1-L2（基礎検索・空間推論）でRAGと同等以上の性能を達成できる |
| H2 | ファインチューニングモデルはL4-L5（意思決定・高度推論）でRAGに劣る |
| H3 | RAG + ファインチューニングの組み合わせが最高性能を達成する |
| H4 | ファインチューニングモデルは推論速度が大幅に向上する |

### 1.3 貢献

本研究の主な貢献は以下の通りである：

1. 地理的POIクエリタスクにおけるRAGとファインチューニングの初の体系的比較
2. タスク難易度レベル別の詳細な性能分析
3. 両アプローチの相補性の実証と、ハイブリッドアーキテクチャの有効性の確認
4. 限られた計算資源（T4 GPU 16GB）でのQLoRA実装手法の確立

## 2. 関連研究 (Related Work)

### 2.1 Retrieval-Augmented Generation

RAGは、Lewis et al. (2020) により提案された手法であり、外部知識ベースからの検索結果をLLMの入力コンテキストに追加することで、事実性と最新性を向上させる。地理情報分野では、POIデータベースとの統合により、位置情報クエリへの対応が可能となる。

### 2.2 Parameter-Efficient Fine-Tuning

LoRA（Low-Rank Adaptation）は、Hu et al. (2021) により提案された手法であり、事前学習済みモデルの重み行列に低ランクの更新行列を追加することで、少数のパラメータのみを学習する。QLoRAは、Dettmers et al. (2023) によりLoRAと量子化を組み合わせた手法であり、消費者向けGPUでの大規模モデルのファインチューニングを可能にした。

### 2.3 地理情報とLLM

地理的質問応答システムにおいては、空間推論能力が重要となる。従来研究では、座標計算や方向判定などの構造化処理とLLMの組み合わせが有効であることが示されている。

│                                                                     │

### 3.2 データ準備

#### 3.2.1 POIデータ

OpenStreetMapから取得した渋谷駅周辺のPOIデータを使用した。

| 項目 | 値 |
|------|-----|
| POI総数 | 1,046件 |
| カテゴリ数 | 12種類 |
| 対象エリア | 渋谷駅周辺（半径約1km） |
| 基準座標 | 緯度35.658034, 経度139.701636 |

#### 3.2.2 空間情報の付与

各POIに対して以下の空間情報を計算・付与した：

- `distance_from_station`: Haversine公式による渋谷駅からの距離（メートル）
- `direction_from_station`: 8方位による方向（北、北東、東、南東、南、南西、西、北西）
- `is_east`: 東西判定（経度比較）

#### 3.2.3 学習データ生成

テストリーク防止のため、テストケースで直接言及されるPOI（東宝シネマ、渋谷東武ホテル等）を学習データ生成元から除外した上で、8パターンの質問-回答テンプレートを用いてデータを自動生成した。

| パターン | 難易度相当 | 生成例 |
|---------|-----------|--------|
| 1. 位置情報 | L1 | 「{POI名}はどこにありますか？」 |
| 2. カテゴリ検索 | L1 | 「渋谷駅周辺の{カテゴリ}を教えてください」 |
| 3. 最近傍検索 | L2 | 「渋谷駅に最も近い{カテゴリ}はどこですか？」 |
| 4. 東西比較 | L2 | 「東側と西側、どちらに{カテゴリ}が多いですか？」 |
| 5. 集約 | L2 | 「{半径}m以内に{カテゴリ}はいくつ？」 |
| 6. 制約付き | L3 | 「{半径}m以内にある{カテゴリ}を教えて」 |
| 7. 推論 | L4 | 「新規{カテゴリ}の出店を検討。競合状況は？」 |
| 8. 感度分析 | L5 | 「範囲を300mから500mに広げると結果は？」 |

生成データはAlpaca形式（instruction, input, output）で保存した。

| データセット | 件数 |
|-------------|------|
| 学習データ | ~1,000件 |
| 検証データ | ~160件 |

### 3.3 QLoRAファインチューニング

#### 3.3.1 QLoRAの原理

QLoRA（Quantized Low-Rank Adaptation）は、以下の2つの技術を組み合わせた手法である：

1. **4bit量子化**: ベースモデルの重みを4bitで表現し、メモリ使用量を大幅に削減
2. **LoRA**: 重み行列 $W$ に対して低ランク行列 $\Delta W = BA$ を追加（$B \in \mathbb{R}^{d \times r}$, $A \in \mathbb{R}^{r \times k}$, $r \ll \min(d, k)$）

```
┌─────────────────────────────────────────────────────────────────┐
│                    QLoRA アーキテクチャ                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ベースモデル（凍結・4bit量子化）                                │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  Qwen2.5-7B-Instruct (7B parameters)                    │   │
│  │  ┌─────────┐  ┌─────────┐  ┌─────────┐                 │   │
│  │  │ Layer 1 │  │ Layer 2 │  │ Layer N │  ... (凍結)     │   │
│  │  └────┬────┘  └────┬────┘  └────┬────┘                 │   │
│  └───────┼────────────┼────────────┼───────────────────────┘   │
│          │            │            │                           │
│          ▼            ▼            ▼                           │
│  ┌───────────────────────────────────────────────────────┐     │
│  │  LoRAアダプタ（学習対象: ~0.1% of parameters）         │     │
│  │  target_modules: q_proj, v_proj                       │     │
│  │  rank = 8, alpha = 16                                 │     │
│  └───────────────────────────────────────────────────────┘     │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

#### 3.3.2 学習設定

T4 GPU（16GB VRAM）での実行を可能にするため、以下の設定を採用した：

| パラメータ | 値 | 説明 |
|-----------|-----|------|
| LORA_R | 8 | LoRAのランク（低次元近似の次元数） |
| LORA_ALPHA | 16 | スケーリング係数 |
| target_modules | q_proj, v_proj | 適用対象モジュール |
| BATCH_SIZE | 1 | バッチサイズ |
| GRADIENT_ACCUMULATION | 16 | 勾配累積ステップ（実効バッチ=16） |
| MAX_SEQ_LENGTH | 512 | 最大シーケンス長 |
| NUM_EPOCHS | 3 | エポック数 |
| LEARNING_RATE | 2e-4 | 学習率 |
| OPTIMIZER | paged_adamw_8bit | 8bit AdamW |

### 3.4 評価方法

#### 3.4.1 比較対象モデル

以下の4つのモデル構成を比較評価した：

| モデル | 構成 | 説明 |
|--------|------|------|
| Baseline | Qwen2.5-7B-Instruct | ベースモデルのみ（RAGなし） |
| RAG | Qwen2.5-7B-Instruct + 構造化RAG | Phase 6システム |
| FT-Base | Qwen2.5-7B-Instruct + LoRAアダプタ | ファインチューニングのみ |
| FT+RAG | Qwen2.5-7B-Instruct + LoRAアダプタ + 構造化RAG | 両アプローチの統合 |

#### 3.4.2 テストケース

55件のテストケースを5段階の難易度レベルで分類：

| レベル | 名称 | 件数 | 説明 |
|--------|------|------|------|
| L1 | 基礎検索 | 10件 | POI位置検索、カテゴリ検索 |
| L2 | 空間推論 | 15件 | 最近傍、密度分析、比較 |
| L3 | 制約充足 | 10件 | 単一・複数制約の充足 |
| L4 | 意思決定支援 | 10件 | 立地評価、出店判断 |
| L5 | 高度推論 | 10件 | 感度分析、不確実性処理 |

#### 3.4.3 評価指標

各回答に対して以下の指標を計算し、レベル別の重み付けで総合スコアを算出した：

| 指標 | 説明 |
|------|------|
| キーワードヒット率 | 期待キーワードの含有率 |
| 座標情報の有無 | 緯度経度（35.xxx, 139.xxx）の含有 |
| 数値の有無 | 距離・件数等の数値の含有 |
| POI名の有無 | 具体的なPOI名の含有 |

レベル別重み付け例：
- L1: キーワード×0.4 + 座標×0.3 + POI名×0.3
- L4: キーワード×0.3 + 数値×0.4 + POI名×0.3

## 6. 考察 (Discussion)

### 6.1 タスク特性と最適アプローチ

実験結果から、タスクの特性により最適なアプローチが異なることが明らかになった：

#### RAGが優位なタスク
- **基礎検索（L1）**: 具体的なPOI情報の検索が必要なタスク
- **カテゴリ検索（basic_category）**: RAG 72.0pt vs FT 47.3pt（+24.7pt）

RAGの優位性は、ベクトル検索による関連POIの正確な特定能力に起因する。ファインチューニングでは、学習データに含まれないPOI名を生成できないため、基礎検索タスクでは限界がある。

#### ファインチューニングが優位なタスク
- **意思決定支援（L4）**: パターン認識と判断が必要なタスク
- **立地評価（decision_location）**: FT 92.8pt vs RAG 76.6pt（+16.2pt）

ファインチューニングの優位性は、学習データから獲得した「出店判断」「立地評価」などの推論パターンに起因する。これらのタスクでは、個別のPOI情報よりも、判断のフレームワークが重要となる。

### 6.2 相補性の実証

FT+RAGが最高スコア（78.5pt）を達成したことは、両アプローチの相補性を実証している。特にL3（制約充足）では、FT+RAGが81.0ptと大幅な優位性を示した。これは：

1. RAGが関連POI情報を正確に提供
2. FTが複数制約の論理的処理パターンを適用

という役割分担が機能したためと考えられる。

### 6.3 推論速度に関する考察

仮説H4（FTは推論速度向上）は棄却された。予想に反してRAGの方が高速（8.13s vs 9.57s）であった理由として：

1. **出力長の違い**: FTモデルは学習データの影響で、より詳細な回答を生成する傾向があり、トークン生成数が増加
2. **RAGコンテキストの効率性**: 構造化されたコンテキストにより、モデルが必要な情報に素早くアクセスできる

### 6.4 改善幅の限界

Baseline（75.7pt）からFT+RAG（78.5pt）への改善幅は+2.8ptにとどまった。これは：

1. ベースモデル（Qwen2.5-7B-Instruct）の事前学習知識が既に高品質
2. 評価指標がキーワードマッチング中心であり、推論品質の差を十分に捉えられていない可能性
3. 学習データ量（~1,000件）が限定的

### 6.5 実験の制約

本実験には以下の制約がある：

1. **単一エリア**: 渋谷駅周辺のみを対象としており、他エリアへの汎化性能は未検証
2. **評価指標の限界**: 自動評価指標では、回答の論理的整合性や有用性を十分に評価できない
3. **計算資源の制約**: T4 GPU（16GB）での実行制約により、LoRAランクやターゲットモジュールを限定

## 7. 結論 (Conclusion)

### 7.1 主要な発見

1. **相補性の確認**: RAGとファインチューニングは相補的であり、FT+RAGが最高性能（78.5pt）を達成
2. **タスク依存性**: 基礎検索ではRAG、意思決定支援ではFTが優位
3. **速度の逆転**: 予想に反し、RAGがFTより高速（8.13s vs 9.57s）
4. **改善幅の限界**: ベースラインからの改善は+2.8ptに留まる

### 7.2 Phase 7以降への提言

| 方針 | 推奨度 | 理由 |
|------|--------|------|
| RAGアーキテクチャ維持 | ★★★★★ | 基礎検索（L1）での大きな優位性、新エリア追加時の柔軟性 |
| 限定的FT導入 | ★★★☆☆ | 意思決定支援（L4）タスクに限定。学習・保守コストの増加に注意 |
| FT+RAGハイブリッド | ★★★★☆ | 最高性能だが、システム複雑性が増加 |
